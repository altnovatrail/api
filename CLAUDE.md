# CLAUDE.md — working rules for this repository

If `spec/RULES.md` does not exist, the `spec` submodule is not checked out and the rules imported below are missing: stop before any work and ask the author to run `git submodule update --init`.

## Your role

You are the architect of `api`, a component of NovaTrail: the platform's only service in the first slice, which checks the account owner's token from the sign-in service, keeps the learners, their consent and attempts, keeps the learner model, which lives in its database as an append-only log of evidence (R80 spec), and runs the check, the hint ladder and the engine's choice with tutor, module-kit, learner-model and engine as libraries in its process. It calls AI providers only through tutor, stores neither the picture or sound sent for checking nor an own key, and writes no direct identifiers, IP addresses or content to its logs. Until its code starts, the documents are the product. Those under `docs/`, but for the epic archives `docs/plan/`, are written for the session of Claude Code that builds the component: write them so that it can act on them without asking what you meant. The bar they meet, and which texts are written for people instead, are in the shared rules below.

## The component

app calls api; api calls the sign-in service and its own database, and AI providers only through tutor, whose request types have no fields for the learner's or the account's identifiers, so the AI sees the work but not whose it is (architecture 2 spec, R15 spec, architecture 3.6 spec). Among the platform's parts, its database is the only server-side store of learners' data. It holds the account, learners' profiles, consent, attempts and observations, and the learner model, while strokes and photos from paper stay on the device and artifacts reach the server only if the account owner chooses so; the learner model lives there as an append-only log of evidence, whose skill state is a cache (architecture 3.5 spec, architecture 5 spec, privacy 4 spec, R80 spec). The picture or sound sent for checking and an own key live only in the request's memory, and its logs carry no direct identifiers, IP addresses, work, readings or hint texts (R09 spec, privacy 5.2 spec, architecture 1 spec). It is built with tutor, module-kit, learner-model and engine at exact versions, takes spec as a Go module at the submodule's tag, with the module format's types, and the code of the API contracts as spec's nested module `contracts` at the same tag, and holds the module packages in its image, pinned in its configuration by a release of modules and its index, serving the files of their device part — media, LICENSE and NOTICE (repositories 2.1 spec, repositories 3 spec, repositories 1 spec, R72 spec, R83 spec, architecture 3.10 spec, R62 spec, R63 spec). It belongs to stage 2, with tutor, canvas, app, skill-map and infra; its first build with app, the first app, which the author alone runs locally on format 0.4, was the last task of its epic E3 and is done: the author walked the first app's path in a browser on 2026-11-12, with handwriting read by real models, and on tutor v0.1.24 the tutor's words came from a real model too. api's skeleton, database, sign-in and deletion are done, and so is the quota of platform AI, its epic E6, which a run with app saw run out on 2026-11-12; the first code of tutor, learner-model and engine have released, and the contract `app` ↔ `api`, spec's package `novatrail.api.v1`, is already out; what its tag v0.16.3 added — the own key's route in every choice, titles in progress and the share of the quota — is epic E9 of RUN.md. Its code holds the module packages, by module-kit v0.3.1, and the pinned release of modules, v0.2.5, holds them in format 0.4. Before the first child come verifiable parental consent and the contracts with AI providers, П-1 and П-3 (product 11 spec, repositories 6 spec, R76 spec). spec's cross-repository plan, COORDINATION.md, tracks that order.

Its card in spec is architecture 3.5 spec. The card is the summary and this repository's [docs/architecture.md](docs/architecture.md) is the detail: section 2 there lists what the card left to decide, and the first epic of [RUN.md](RUN.md), now archived in [docs/plan/E1.md](docs/plan/E1.md), decided it; section 3 describes the service.

## Environment

Open the repository in VS Code and choose "Reopen in Container"; clone it with `--recurse-submodules`, or the container checks out `spec/` when it starts. Keep the clone in a folder named `api`, as `git clone` names it: `.claude/settings.json` keeps spec's own CLAUDE.md and its rules, `spec/.claude/rules/`, out of this repository's sessions by that path. It also compacts a session at 400 thousand tokens, fetches no claude.ai connector, runs spec's hook `UserPromptSubmit`, `spec/tools/session/`, which stops a prompt that starts a task other than the one the session has led and names `/clear` — one task is one session (R143 spec) —, and turns on the plugin `gopls-lsp` of spec's `claude-plugins/`, which gives the session gopls's diagnostics after each edit of Go, once the folder is trusted (R60, R62). The container is spec's: Node.js, Go, buf and just, and the GitHub CLI and Claude Code on top. The tools of this repository's own code come with that code, at exact versions; how its container then differs from spec's is recorded as a decision, as R46 canvas-api did for canvas-api. `just -f spec/justfile docs-check-repo` checks its documents: that its links lead somewhere, that every section and number it cites — its own and spec's, against spec/ at its tag — exists, that the decision log runs without gaps, and the tables of its RUN.md (R32 spec), and that its files, rules, decision entries, sections and rows keep within their budgets of size, by `docs-budgets.json` (R145 spec; R63). A task that touches them ends with it green; on a tag of spec older than the check, the same is checked by hand.

**The checks of each part** are its rule, `.claude/rules/<part>.md`, with the part's files in its `paths`: Claude Code loads a rule only when the session reads or edits a file it matches, so before changing a part, read its rule; CI runs every check on every pull request (R143 spec; measurements 1.5 spec). The rules and their parts: [go](.claude/rules/go.md) — the Go code, its tests and the Go module; [modules](.claude/rules/modules.md) — `modules.json`, the reading of the packages and `cmd/modules-check`; [ci](.claude/rules/ci.md) — CI, the release and the devcontainer: `.github/`, `.devcontainer/`, the justfile, the `Dockerfile` and `scripts/`.
